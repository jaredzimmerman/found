# T06: Source report sidecar and an honest final message
Tier: sonnet · Reviewer: opus · Deps: T05

## Brief
Goal: the build can say, per source, how many rows it registered and kept, and which sources failed or were skipped; the closing line stops claiming success when a module was skipped.
Contract: PLAN.md C2, C3; validator CLI in `build/validate-feed.mjs` (already built, T07).
Files: `build/fetch.mjs` (and `build/dc-fetch.mjs` only if trivial), `tests/source-report.test.mjs`, extend `tests/replay/run.sh` to also check the report (copy the report into the `--out` dir and verify it).
Rules:
- Every row passed to `register()` must carry a stable lower-case `row.source` ("dothebay" for rows from `add()` / citywide / venues, plus the existing names normalized: funcheap, citylights, omnivore, foopee, decentered, luma, sfstation, sfcb, workshopsf, clayroom, scrap, espn). Today some rows have none; the `source` key is still deleted before `events.json` is written (output byte-identical to the golden).
- Count `registered` at registration and `kept` for rows surviving to the written feed; write `build/.source-report.json` per C2 just before the feed is written. `failed` = a source whose fetches all failed per the `fetchFailureReport` ledger or that threw; `skipped` = module unavailable (the existing `omnivore: unavailable ... skipped` path); `reason` holds the one-line message.
- The last console line: `every source fetch succeeded` ONLY when none failed and none skipped; otherwise `sources: N ok, M skipped (names), K failed (names)`.
- A source that registers 0 rows with no failure is `ok` with `kept: 0` (sfcb/clayroom/scrap legitimately return 0 on many days).
Acceptance: `bash tests/replay/run.sh` exits 0 (identical to golden); in the replay output `.source-report.json` exists, `sum(kept) == totals.kept == events.length` (192 in the golden), omnivore is `skipped`, and `node build/validate-feed.mjs --events <out>/events.json --report <out>/.source-report.json --floors build/source-floors.json` exits 0; `bash tests/run-all.sh` exits 0.
Constraints: no change to `events.json` bytes; no new dependencies; keep the diff to fetch.mjs small; do not touch http.mjs semantics.

## Result
Files: build/fetch.mjs (srcName/pushRow/reportOf, run() wrapper per source, report write, honest last line; landed in an earlier checkpoint swept by the parallel chain), tests/replay/run.sh (copies .source-report.json to --out, checks sum(kept)==totals.kept==events.length, runs validate-feed), tests/source-report.test.mjs (new).
Acceptance: `bash tests/replay/run.sh` -> "replay OK", events identical (192) and dc identical (26). Report: 12 ok, omnivore skipped, sum(kept)=192. Last line: `sources: 12 ok, 1 skipped (omnivore), 0 failed ()`. `bash tests/run-all.sh` exit 0 (see below).
Failed rule: threw, or registered 0 with a ledger failure for that source.
Open issue (needs lead): `validate-feed.mjs` exits 1 on the golden feed: 10 sfstation rows have `categories: []` (C4 requires non-empty). Output must stay byte-identical, so run.sh reports this as a NOTE and does not gate on it. Fix sfstation categorization (changes golden) or relax the check; otherwise the first real build will be rejected by T08's validator.

Issues:
1. (blocking) build/fetch.mjs:1451 - citywide() calls markFailed() for a single failed band, which sets threw=true, so line 2596 marks the whole dothebay source `failed` even when the other band and venues() registered 100+ rows. This breaks the brief's rule (failed = all fetches failed per the ledger, or the source threw); citywide catches its own errors, so it did not throw. Effect: one DoTheBay band timeout makes the report and last line say `1 failed (dothebay)` with kept ~125. Fix: record the band with `noteFailure(url, err)` (the ledger, like venues() at 1489) instead of markFailed. The `fails` check at 2629 still keeps the success line from printing.
2. (lead, not fixable inside T06) Acceptance clause "validate-feed exits 0" fails: 10 sfstation rows in the golden have `categories: []`, and C4 requires a non-empty array. The output must stay byte-identical, so T06 cannot fix this. The run.sh NOTE and the Result's open issue are correct. It matters in production: T08's build-site.sh will REJECT every real build that contains an uncategorized sfstation row, so the site stops updating. Choose a fix: categorize sfstation (and re-golden), drop rows with no category in fetch, or relax C4.
3. nit: build/fetch.mjs:2630 prints `0 failed ()` / `0 skipped ()` with empty parens; omit the parens when the list is empty.
4. nit: the fetch.mjs part of T06 landed in the T08 commit ecd6b18, not a `ladder: T06` commit (the Result discloses this). `git log --grep "ladder: T06"` does not show it.
5. nit: build/fetch.mjs:2018-2022 `source: "City Lights"` inside the chromium.launch options, and the duplicate `source:` key at 1953/1975, are baseline quirks (last key wins -> citylights), not T06's. Harmless.
6. nit: build/fetch.mjs:1324/1363 - when a richer duplicate replaces a row, `kept` goes to the new row's source while `registered` stays with the old one, so `kept <= registered` per source (asserted in tests/source-report.test.mjs) is not guaranteed in general. It holds on the golden.
7. nit: build-site.sh greps `every source` from the fetch log, so the new `sources: ...` line is not shown in its console summary (T08's file).
