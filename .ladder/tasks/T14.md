# T14: Make build-site.sh survive DreamHost's flaky node launches
Tier: opus · Reviewer: fable · Deps: T08

## Brief
Goal: on the shared DreamHost host, node 18 intermittently aborts at launch (`pthread_create: Resource temporarily unavailable` -> SIGABRT/exit 134, sometimes SIGTRAP 133) or hangs at startup, and `bash: fork: retry` was seen once (T08/T09 reviews, 2026-10-07). Today one such flake in any `node` step turns a whole 6-hourly run into `fatal` and the site stays stale until the next cron slot. Make the build resilient WITHOUT hiding real failures.
Contract: PLAN.md C5, C6, C8; read `.ladder/tasks/T08.md` and `.ladder/tasks/T09.md` (what they saw and what deploy's quick-step retry does; reuse that pattern/helper if it is in `ops/lib.sh`, but build-site.sh must stay self-contained on DreamHost: do not source files outside the deploy unit).
Files: `build-site.sh`, `tests/build-site.test.sh` (new cases), `tests/fixtures/` stubs as needed. No other build/*.mjs changes.
Rules:
- A `run_node` wrapper used for EVERY node invocation in build-site.sh (test-imports, fetch, dc-fetch, validate-feed, record-run, inline `node -e` helpers). Quick steps (everything except fetch/dc-fetch): per-attempt `timeout 60s`, up to 3 attempts, retry ONLY when the failure is a launch flake: exit 134 or 133 or 124 (hang) or 139, or exit 1 with the stderr containing `pthread_create` / `Resource temporarily unavailable` / `fork: retry`. A script/logic failure (any other exit, e.g. validator exit 1 with its normal message, syntax error) is NEVER retried. Backoff 3 s, 8 s. Each retry prints one line `retry node <step> (attempt n/3, reason)` into the run log and increments a counter surfaced in history/status (`node_retries`).
- fetch.mjs and dc-fetch.mjs: retry ONCE, and only if the process died of a launch flake within the first 90 s (before it could have fetched much). A death after 90 s, or any normal exit, is not retried (it would double the load on the sources and mask real breakage). fetch stays under `FETCH_TIMEOUT`; the retry shares that overall budget.
- Reduce the cause too: export `UV_THREADPOOL_SIZE=2` and add `--v8-pool-size=1` / `NODE_OPTIONS` ONLY if you verify on DreamHost (node 18.19.1) that node accepts them and still runs the replay-equivalent workload; document the finding. Do not guess flags.
- `record-run.mjs` must be invoked with the same wrapper; if it still cannot run after 3 attempts, the script appends a minimal hand-written JSON line (printf, no node) to `logs/history.jsonl` and writes `logs/status.json` via a bash fallback so the watchdog never loses a run silently.
- New test cases in `tests/build-site.test.sh` using stub node-launch failures (a stub `node` earlier in PATH that aborts/hangs/exits N the first k times): flake then success => `published` with `node_retries` >= 1; three flakes => fatal at that stage; real validator rejection => NOT retried (one attempt, outcome `rejected`); fetch flake within 90 s retried once; fetch failure after the window not retried; record-run fallback line is valid JSON.
Acceptance: `bash tests/build-site.test.sh` exits 0 on the Mac, and ALSO on DreamHost via `tar c . | ssh hermes 'ssh dh-backup "rm -rf /tmp/t14 && mkdir /tmp/t14 && tar x -C /tmp/t14 && cd /tmp/t14 && bash tests/build-site.test.sh"'` (retry the harness itself once if node flakes before the first test starts; clean /tmp/t14 after); `bash tests/run-all.sh` exits 0; `bash tests/replay/run.sh` exits 0.
Constraints: no password handling; prod untouched (temp dirs in /tmp only); bash 3.2/4 and DH compatible; keep the diff to build-site.sh surgical (stage bodies unchanged apart from calling the wrapper).

## Result
Files: `build-site.sh` (helpers + every node call routed through them; stage bodies otherwise unchanged; `run_bounded`/`dur_secs` moved above the EXIT trap so the trap can use them, and `run_bounded` now passes the caller's stdin with `<&0`), `tests/build-site.test.sh` (cases 15-25), new `tests/fixtures/stub-node.sh` (via `W72_NODE`, because build-site.sh puts /usr/bin first on PATH, which would shadow a PATH stub on DH).

**Root cause (verified on DH 2026-10-07):** the account's cgroup `/customer/cpu_88_89/limits/indigokarasu` has **`pids.max = 25`** (threads count); `pids.events` showed `max 91` before this work. sshd/systemd/sftp-server baseline is ~5-8 tasks. Plain node 18 = 7 tasks at start, 11 once the libuv pool starts. T09's "not a per-user limit" missed this file.

**Node flags (verified on DH node 18.19.1, not guessed):** `NODE_OPTIONS=--v8-pool-size=1` is accepted (shows in execArgv/env), `UV_THREADPOOL_SIZE=2` honoured. Task counts: idle 7 -> 4; with fs I/O 11 -> 6; replay run peak node tasks 12 -> 7. `tests/replay/run.sh` on DH with the flags: events 192 + dc 26 identical to golden, 4.95 s vs 4.94 s. So build-site.sh now exports both (NODE_OPTIONS appended, not overwritten). Not measurable offline: UV_THREADPOOL_SIZE=2 also caps parallel DNS lookups in the live fetch (paced, so expected fine; watch fetch duration in history after rollout).

Behaviour: `run_node` (quick steps: version, imports, dc-check, validate, summary, served, assets, count, dc-recheck, dc-age, record-run): 60 s per attempt, 3 attempts, backoff 3 s/8 s, retry only on 134/133/139/124 or exit 1 + `pthread_create|Resource temporarily unavailable|fork: retry`; an exhausted exit-1 flake returns 75 so validate never reads it as a rejection. `run_node_long` (fetch, dc-fetch): one retry only if it died of a flake within 90 s, inside the remaining FETCH_TIMEOUT; first log kept as `.fetch.log.flaked`. dc-fetch is now bounded by FETCH_TIMEOUT (was unbounded). Retry line `retry node <step> (attempt n/N, reason)` goes to the run log via fd 7; `node_retries` added to the history line (when > 0) and status.json (always) by an awk patch after record-run (record-run.mjs untouched per brief). record-run gets 15 s per attempt; if it still fails, `record_fallback` printf-appends a history line (`recorded_by:"bash-fallback"`) and rebuilds status.json from history + previous status (last_success, consecutive_failures, sources carried, deployed_sha, feed_generatedAt).

Open issues:
- **For T09/T12 (ops/lib.sh, not my file):** plain `tests/run-all.sh` on DH hung for 10 min: `tests/record-run.test.mjs` (11 tasks) spawnSync'd a child node that stalled at 5 tasks, total exactly 25 = pids.max, so neither could proceed and even `ls` got `fork: retry`. ## Review
Round 1 (fable, 2026-10-07). Verdict: **approve**.

Ran every acceptance command myself, real output:
- Mac `bash tests/build-site.test.sh` -> `25 cases, 63 passed, 0 failed, 2 skipped (41s)`, exit 0 (skips = no flock/timeout on macOS)
- DH, exact brief command via `tar c . | ssh hermes 'ssh dh-backup ...'` -> `node v18.19.1, bash 5.2.21, flock=1 timeout=1` ... `25 cases, 69 passed, 0 failed, 0 skipped (99s)`, exit 0, first try (no harness retry needed); `/tmp/t14*` and sandboxes cleaned after (0 left)
- Mac `bash tests/run-all.sh` -> `ALL PASS: 45 checks/files`, exit 0
- Mac `bash tests/replay/run.sh` -> `[events] identical: 192`, `[dc-events] identical: 26`, `replay OK (fixtures: 613 recorded 2026-10-07T22:21:30.000Z)`, exit 0

Adversarial read of build-site.sh (no code edited):
- Masking: `node_flake` (build-site.sh:212-222) retries only 134/133/139/124 or exit 1 whose stderr names pthread_create / `Resource temporarily unavailable` / `fork: retry`. Each attempt truncates `$err`, so a flake followed by a real validator exit 1 breaks out with rc=1 -> `rejected`; three exit-1 flakes return 75 so validate never reads a launch failure as a rejection (test case 17 covers it). The patterns are glibc-cased; libuv's EAGAIN text is `Unknown system error -11` (node 22) / lowercase on 18, so a network error in a fetch log cannot false-match.
- Double load: `run_node_long` (build-site.sh:271-288) retries once, only if rc != 124 and the death was inside `NODE_FLAKE_WINDOW`, with the remaining `FETCH_TIMEOUT` minus backoff; a death after the window or a normal exit returns as-is (cases 21-23). Hangs are never retried for fetch, per brief.
- Lock/trap: `run_bounded` moved above the EXIT trap and now passes stdin (`<&0`), needed because a backgrounded job would otherwise read /dev/null. `on_exit` runs record-run under `NODE_BOUND=15s` (3 x 15 s + 11 s backoff < the 60 s KILL grace), and falls back to `record_fallback` (printf only) when node cannot start: history line + status.json rebuilt from history and the previous status; tested chained (fallback -> fallback -> record-run reads it back, cases 24). Retry lines go to fd 7 so a retry inside `$(...)` (count, dc-age, served, assets) cannot corrupt the captured value.
- Partial writes: `annotate_node_retries` and `record_fallback` both write `tmp` then `mv -f`; the history append is a single printf with a leading-newline guard when the file lacks one.
- Flags: `NODE_OPTIONS=--v8-pool-size=1` appended (not overwritten) and accepted by node 22 here (execArgv shows it) and by node 18.19.1 on DH (the DH suite would have failed on every node launch otherwise); replay output identical per Result.
- Constraints: no password handling; temp dirs only on DH; bash 3.2 and 5.2 both green; diff to stage bodies is call-site substitution only; W72_NODE instead of a PATH stub is justified (build-site.sh:98 prepends /usr/bin).

Issues (none blocking):
- nit: build-site.sh:353-357 - in the `locked-skip` path `annotate_node_retries` still rewrites history.jsonl (awk > tmp; mv) without holding the build lock, while the lock holder may append its own line. Needs a record-run flake during a locked-skip plus a millisecond-wide race, so not blocking; the simplest fix is to skip the history rewrite for locked-skip too, as status.json already is.
- nit: build-site.sh:282 - `.fetch.log.flaked` / `.dc-fetch.log.flaked` are never removed; harmless (one file each, overwritten on the next flake).
- nit: build-site.sh:233-234 - the mktemp-failure fallback runs node unbounded and, via `run_node_stdin`, with an already-consumed stdin; only reachable when mktemp in `$LOGS` fails, at which point the run is already dying.
- note for the lead (not T14's files): `ops/lib.sh:174` runs `tests/run-all.sh` on DH without `NODE_OPTIONS`/`UV_THREADPOOL_SIZE`; the Result shows it can deadlock under pids.max=25. It is bounded by `DEPLOY_PREFLIGHT_BOUND` (1200 s) with prod untouched, so a deploy fails loudly rather than hangs, but it belongs to T09/T12.
