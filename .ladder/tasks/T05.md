# T05: Shared HTTP helper with timeouts, retries and a global deadline
Tier: opus · Reviewer: fable · Deps: T04

## Brief
Goal: every network read in the scrapers goes through `build/http.mjs` (PLAN C7). Today `j()` has no explicit timeout, nothing retries, nothing bounds the whole run.
Contract: PLAN.md C7. Replay harness: `tests/replay/README.md` (I/O map and rules).
Files: new `build/http.mjs`, `tests/http.test.mjs`; migrate call sites in `build/fetch.mjs`, `build/shared.mjs`, `build/foopee.mjs`, `build/sfstation.mjs`, `build/sucuri.mjs`, `build/dc-fetch.mjs`, `build/manual-venues.mjs`, `build/citylights-parse.mjs` as found. Do NOT touch `build-site.sh`, `build/validate-feed.mjs`, `build/test-imports.mjs`.
Rules:
- API per C7: `getJson(url, opts)`, `getText(url, opts)`, plus `startDeadline(ms)` / `DeadlineError`. Keep every existing request header, UA string, redirect behavior and the existing pacing/sleeps exactly (output and request URLs must not change: replay is keyed by METHOD+URL).
- Retry only network errors, 408/425/429/5xx; never other 4xx; honor `Retry-After` (seconds or HTTP date) capped at 30 s; backoff 1 s then 3 s with jitter. Timeouts via `AbortSignal.timeout`. The deadline: after `startDeadline(ms)` expires every call throws `DeadlineError` at once and a single unref'd timer ends the process with exit code 124 and one stderr line, never writing `events.json` (verify the write happens only at the end of `main()`).
- Failures still flow into the existing `noteFailure` ledger / `fetchFailureReport()` so the end-of-run summary keeps working. A retried-then-succeeded request is NOT a failure; log a one-line `retry` note per retried URL (count them, print the total at the end).
- Call `startDeadline(Number(process.env.FETCH_DEADLINE_MS || 720000))` from `main()` in fetch.mjs and dc-fetch.mjs.
- Sync `curl` HEAD helpers (`fetchSync` in fetch.mjs and shared.mjs) already have `--max-time`; leave their behavior, but note them in the Result.
- Unit tests (`tests/http.test.mjs`, local `node:http` server on port 0, >= 20 checks): success; JSON parse error is not retried; 500 then 200 retries and succeeds; 429 with Retry-After honored (use tiny values via an injectable clock/backoff option, tests must run in < 5 s); 404 not retried; hang -> timeout -> retried -> final error; DeadlineError after deadline; request headers preserved; `Retry-After` cap.
Acceptance: `bash tests/run-all.sh && bash tests/replay/run.sh` both exit 0 (replay output identical to the golden), AND `grep -nE "(^|[^.A-Za-z_])fetch\(" build/*.mjs | grep -v "^build/http.mjs" | grep -v test-` prints nothing (no raw fetch left outside http.mjs; list any deliberate exception in the Result with the reason).
Constraints: node 18.19 compatible (DreamHost) and node 22; no dependencies; output byte-identical to the golden; keep diffs to call sites small and mechanical; never run the scrapers against the live network from here (use replay); if a path cannot be replayed (e.g. Sucuri), say how you tested it.

The replay stdout logs of both scrapers are also byte-identical to the baseline code's logs.

Verified also: `tests/http.test.mjs` passes on DreamHost node v18.19.1 (temp dir in /tmp, removed). Under replay with `FETCH_DEADLINE_MS=5`, both `fetch.mjs` and `dc-fetch.mjs` exit 124 with one stderr line and write no output file (REPLAY_FAST 0 and 1).

Notes / open issues:
- Two non-call-site text edits so the grep is clean: the failure-report string `source fetch(es) failed` became `source request(s) failed`; a comment reworded. No consumer greps the old text.
- Behavior deltas (logs only, output identical): `j()` now has a 20 s per-attempt timeout (had none); dc-fetch page walk now logs the "PARTIAL" line on a non-2xx (it used to stop silently); luma top-level non-2xx logs `luma: Error: HTTP n` instead of `luma: HTTP n`.
- Deadline expiry found by a call before the timer could run (sync work) takes the same exit-124 path. A backoff that would outlast the deadline fails that one call with DeadlineError; the run still ends at the deadline.
- Sync curl HEAD helpers (`fetchSync` in fetch.mjs and shared.mjs, curl in sucuri.mjs) are untouched; they block the event loop up to their `--max-time`, so the deadline fires at most that late.
- Retry paths are not exercised by the replay (every recorded fetch was a 200); they are covered by the unit tests against a local server.

- "Logs identical to baseline": replayed the pre-T05 commit (9835618, `git archive`) against the same fixtures with `--out` and `cmp`'d both scraper logs with the current tree's: identical (32 + 10 lines, 0 `retry:` lines). So request order, pacing and log text are unchanged.
- `writeFile` appears exactly once in each of `fetch.mjs` (2548) and `dc-fetch.mjs` (349), both directly after `stopDeadline()`; `expire()` calls `process.exit(124)` synchronously so no aborted-fetch rejection can be observed first.
- Constraints: both T05 commits leave `build-site.sh`, `validate-feed.mjs`, `test-imports.mjs` untouched; `http.mjs` imports only `node:events` / `node:perf_hooks`, no `AbortSignal.any`; call-site diffs are 44+/44- across five files; the old `source fetch(es) failed` text has no consumer outside `.ladder/`. Node 18.19 compatibility: no node 18 on this Mac, so it rests on the author's DreamHost run plus an API read (`AbortSignal.timeout`, `setMaxListeners(0, signal)`, `body.cancel()` all exist in 18.x).

Issues (none blocking):
- nit: `build/fetch.mjs:2433`, `build/dc-fetch.mjs:227` — `Number(process.env.FETCH_DEADLINE_MS || 720000)` with a non-numeric value (a cron typo) gives `NaN`, and `startDeadline` (`build/http.mjs:66`) then silently installs no deadline. One stderr warning there would stop the safety net vanishing quietly. The brief dictated this exact call, so not a breach.
- nit: `build/fetch.mjs:2548`, `build/dc-fetch.mjs:349` — the write is a plain `writeFile`, not write-temp-then-rename; a SIGKILL from an outer `timeout` during the write can leave a truncated feed. Pre-existing and outside this brief (T08's validator is the backstop), noting it for T13.
- nit: `build/fetch.mjs:2305` — luma per-event pages now retry 5xx with the 1 s + 3 s backoff (before: one try, silent skip). Timing-only, bounded by the deadline; worth a line in the Result's behavior deltas.
- nit: `build/http.mjs:97-98` — on macOS stdout to a pipe is async, so `process.exit(124)` may drop the last `console.log` lines; on Linux (DreamHost) pipe writes are synchronous, so prod is fine.
