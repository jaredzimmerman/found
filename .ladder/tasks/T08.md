# T08: build-site.sh: lock, timeouts, modes, history/status, validator

## Brief
Goal: the cron entry point becomes safe to run concurrently, bounded in time, observable, and gated by the validator; and it can run in sandbox modes so deploys can be proved before they touch prod.
Contract: PLAN.md C4 (CLI), C5 (history/status), C6 (lock/limits), C8 (modes). Validator is built: `build/validate-feed.mjs` (read its CLI and tests).
Files: `build-site.sh`, new `build/record-run.mjs` (pure function + CLI that appends the history line, trims to 500 lines, and writes `logs/status.json`, so bash never hand-builds JSON), `tests/record-run.test.mjs`, `tests/build-site.test.sh` (+ any helper under `tests/fixtures/` such as a stub fetch.mjs / stub run-levels.sh). Do not touch other build/*.mjs.
Rules:
- New env knobs (defaults = today's behavior): `ROOT` (default `$HOME/whattodo72.com`), `SITE_URL` (default `https://whattodo72.com`; replaces every hard-coded URL in stages 6-7), `DRY_RUN=1`, `STAGE_ONLY=1`, `RUN_ID` (default `$(date -u +%Y%m%dT%H%M%SZ)-$$`), `BUILD_TIMEOUT` (default `25m`), `FETCH_TIMEOUT` (default `15m`).
- Lock: `exec 9>"$TEST/.build.lock"; flock -n 9` or log + history outcome `locked-skip` + exit 0. Overall bound: re-exec under `timeout "$BUILD_TIMEOUT"` once (guard variable); `node fetch.mjs` under `timeout "$FETCH_TIMEOUT"` with `FETCH_DEADLINE_MS` exported (default 12 min).
- Logging: tee the whole run to `$TEST/logs/runs/$RUN_ID.log`, keep the last 30; rotate `logs/build.log` when over 1 MB (cron appends to it). A `trap` on EXIT/TERM/INT ALWAYS calls `record-run.mjs` with outcome (`published|rejected|fatal|dry-run|stage-only|locked-skip`), stage reached, duration, total, per-source kept (from `build/.source-report.json` if present), git sha (`build/.deployed-sha` if present), fatal messages. The script must still exit non-zero on failure.
- Validation: replace the inline `validate_feed` with `node validate-feed.mjs --events events.json --report .source-report.json --floors source-floors.json --history $TEST/logs/history.jsonl --live-url $SITE_URL/events.json`; a fatal => outcome `rejected`, live and /test untouched. Keep the old checks' intent (3 days, includes today) - they now live in the validator. Keep stage 2b (DC feed) behavior unchanged. If `.source-report.json` is missing (old fetch.mjs), validate without it and warn.
- Modes: `DRY_RUN=1` stops after validation (stages 0-3 incl. levels is NOT run: skip `run-levels.sh` in dry-run), prints a summary, never writes /test or live. `STAGE_ONLY=1` publishes /test (+ static assets) and stops before promote.
- Never edit this file in place from within itself; the test must prove a mid-run replacement of build-site.sh by `mv` does not corrupt a running instance (deploy relies on rename).
- Tests (`tests/build-site.test.sh`, offline, < 60 s, node 22): temp ROOT with stub build tree (copy real build-site.sh, validate-feed.mjs, record-run.mjs, source-floors.json; stub fetch.mjs that writes `tests/fixtures/feed-good.json` (and a matching `.source-report.json`) or a bad variant per env; stub run-levels.sh) and `python3 -m http.server` serving the temp docroot as `SITE_URL`. Cases: good run publishes /test and live byte-identical + history `published` + status.json fields; bad feed (string categories) => rejected, live unchanged; stub fetch exit 1 => fatal, live unchanged; second instance while the first runs => `locked-skip`, exit 0; `DRY_RUN` writes neither /test nor live; `STAGE_ONLY` writes /test only; a hung stub fetch is killed by `FETCH_TIMEOUT=2s`, outcome `fatal`; history trims to 500; run log retention 30.
Acceptance: `bash tests/build-site.test.sh` exits 0 and prints the case count (>= 9), `node tests/record-run.test.mjs` exits 0, `bash tests/run-all.sh` exits 0 (the .sh test is auto-discovered).
Constraints: bash 4-compatible AND works on DreamHost (flock, timeout, python3 available) and macOS test runs (use `command -v flock` and skip lock cases with a clear SKIP line on macOS if flock is absent, but they MUST run on DreamHost: say in the Result how you ran them there via `tar c . | ssh hermes 'ssh dh-backup "..."'` in /tmp, cleaned up after); `set -euo pipefail` discipline kept; no secrets; prod untouched.
