# T07: Feed validator
Tier: sonnet · Reviewer: opus · Deps: T03

## Brief
Goal: a validator that would have blocked the 2026-10-07 bad feed (12 events with string `categories`, a `null` venue), plus per-source floors and a delta guard.
Contract: PLAN.md C3, C4, C5 (history format) and C2 (report format).
Files: `build/validate-feed.mjs`, `build/source-floors.json`, `tests/validate.test.mjs`, `tests/fixtures/feed-good.json` (60 real events trimmed from `curl -s https://whattodo72.com/events.json`, keeping the real envelope keys `generatedAt, days, counts, neighborhoods`), do NOT edit `tests/run-all.sh`: it auto-discovers `tests/*.test.mjs|sh|py`.
Rules:
- Export `validateFeed(feed, ctx)` (pure, no I/O) and a CLI wrapper; node 18 + node 22 compatible, no dependencies.
- Taxonomy: derive the allowed category list from `build/fetch.mjs` (the `MAP`/`KEYWORDS` values and fallbacks such as "Community", "Sports & Fitness") by exporting or re-reading the single source of truth; do NOT hard-code a second copy that can drift. If extraction needs a small export in fetch.mjs, make it side-effect free (fetch.mjs runs `main()` on import: check how it is guarded before importing it!).
- `source-floors.json` seed: `{"dothebay":{"min":60,"required":true}}` plus optional (required:false) entries `funcheap` 8, `foopee` 5, `luma` 2, `sfstation` 3. Source-name matching is case-insensitive; a floors entry with no matching report entry is a warning, not a fatal.
- Delta guard per C4, reading `logs/history.jsonl` (C5). Tests must cover: <3 published runs -> uses `ctx.liveTotal`; `--accept-delta`; one-shot `.accept-delta` file consumed; >160% is only a warning.
- Tests (>= 25 checks): good feed passes; the string-categories regression, null-where-string, duplicate ids, `source` key present, bad date, `days` wrong length, missing today, empty categories, unknown category, floor breach required vs optional, delta fatal and warning cases all behave as C4 says.
Acceptance: `node tests/validate.test.mjs` exits 0 and prints the check count; `bash tests/run-all.sh` still exits 0.
Constraints: report problems with the event id and field; never mutate the feed; no network in tests; do not edit build/fetch.mjs behavior.

## Result
Files: build/validate-feed.mjs, build/source-floors.json, tests/validate.test.mjs, tests/fixtures/feed-good.json (60 real events from live events.json, real envelope keys).
- Taxonomy is read from fetch.mjs source text (never imported: it runs main()): CATEGORIES list + MAP values + KEYWORDS categories + categorize() literal fallbacks. No second copy.
- validateFeed(feed, ctx) is pure; ctx.categories is required (CLI loads it). CLI flags per C4 plus --out, --accept-file, --today, --fetch-src (for tests). Live-url fetch uses node:https, not fetch(). One-shot build/.accept-delta is consumed only when it actually downgraded a delta fatal.
- endMinutes/startMinutes accept -1 (the real "unknown" sentinel in the live feed); the brief said "ints".
Acceptance: `node tests/validate.test.mjs` -> `70 passed, 0 failed`; `bash tests/run-all.sh` -> `ALL PASS: 31 checks/files`.
Open issues (needs a decision before T12 deploy):
1. The LIVE feed today (192 events) has 10 sfstation events with `categories: []` (ids sfstation-2026-10-0x-...). Per C4 these are fatal, so the validator would reject the current production feed. The sfstation path in the scraper needs a "Community" fallback (output change, not in T07 scope), or C4 must allow it.
2. A null `venue` in the live feed was not found (0 in the 192 sampled); address null is common (17) and allowed.

## Review
Round 1 (opus): **approve**

Acceptance, run by the reviewer on node v22.22.3: `node tests/validate.test.mjs` printed `70 passed, 0 failed` and exited 0. `bash tests/run-all.sh` printed `ALL PASS: 31 checks/files` and exited 0. Node 18 is not installed here, so node 18 was not run. The code uses no API newer than node 12/14 (matchAll, Intl, fs.rmSync, spawnSync).

Constraints:
- Problems name the event id and field: yes, as `event <id>: <field>: <msg>` (build/validate-feed.mjs:159), with a 40-item cap that states the total.
- The feed is never mutated: yes (sorting works on a copy at :64; there is a test for it). The CLI only unshifts into its own result.
- No network in tests: yes. No test passes `--live-url`, and the CLI tests write `--out` and `--accept-file` into a temp dir.
- fetch.mjs behavior unchanged: yes. `git diff 684e438 HEAD -- build/fetch.mjs` is empty.
- Taxonomy has a single source of truth: yes. It is read from fetch.mjs source text and never imported (fetch.mjs:2581 calls main() unguarded). It extracts the expected 11 categories. Every literal `categories:` in build/*.mjs (manual-venues "Talks & Workshops", fetch.mjs:2438 "Sports & Fitness") is in the set.
- Floors seed matches the brief. Source-name matching is case-insensitive. A floors entry with no report entry is a warning.
- Delta guard matches C4: median of the last 7 published runs; liveTotal when fewer than 3; above 160% only warns; --accept-delta and the one-shot file downgrade the fatal. All are covered by tests.
- The Result section's claims are true of the tree.

Issues:
- Not a T07 defect, but it blocks T08/T12 (contract conflict): build/sfstation.mjs:192 emits `categories: []` on purpose. Under C4 that is fatal, so the validator will reject every production feed that contains sfstation rows. The implementer flagged this correctly in Open issue 1. It needs a decision before T08 wires the validator in: either add a fallback in sfstation or relax C4.
- nit: build/validate-feed.mjs:174-175. When no report is supplied, or a REQUIRED source has no report entry, the floor only warns (fail-open). The brief asked for this, but T08 must always pass a fresh `--report`. The validator does not check `report.generatedAt` against the feed, so a stale report would also pass.
- nit: build/validate-feed.mjs:201. When the baseline is 0 (for example a live total of 0), the delta guard is skipped without any warning.
- nit: tests/validate.test.mjs, the regression CLI call (`badfeed.json`). It omits `--accept-file`, so it checks the real `build/.accept-delta` path. That is harmless, because no delta fatal means nothing is consumed, but it is not hermetic.
- nit (process): the T07 files were swept into the parallel commits 4d91c0e (T11 review) and 427bbda (T10). Because of that, `git log --grep "ladder: T07"` shows only a 1-line test change.
