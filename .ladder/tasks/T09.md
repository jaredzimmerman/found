# T09: ops/deploy.sh (preflight, dry-run, atomic swap, rollback)
Tier: opus · Reviewer: fable · Deps: T08

## Brief
Goal: replace "scp a file into the live build dir" with one reversible command that cannot ship a tree that does not even parse.
Contract: PLAN.md C1 (what is deployed vs never touched), C8 (modes), C9 (deploy).
Files: `ops/deploy.sh`, `ops/lib.sh` (shared helpers), `tests/deploy.test.sh` (selftest against a SIMULATED remote), docs section in `docs/ARCHITECTURE.md` ("Deploying") and the `ops/` line in `docs/AGENTS.md`.
Rules:
- All remote work goes through one `remote()` function (script on stdin) and one `remote_extract()` (tar stream on stdin). Default transport: `ssh hermes 'ssh -o BatchMode=yes dh-backup bash -s'`. `DEPLOY_TRANSPORT=local` + `DEPLOY_REMOTE_HOME=<dir>` runs the same code against a temp HOME on this machine (used by the selftest; must exercise the real code paths, not a copy).
- Flow: refuse unless git tree is clean and HEAD is pushed (`git branch -r --contains HEAD`); `git archive HEAD` -> `~/whattodo72.com/test/.deploy/<sha>/` on the remote; remote preflight with the remote's node: `node --check` every `build/*.mjs`, `bash -n` every `*.sh`, `bash tests/run-all.sh`; then sandbox dry-run: build a sandbox ROOT under `.deploy/<sha>/sandbox` (copy the staged build + the live generated state + `logs/history.jsonl`), run `DRY_RUN=1 ROOT=<sandbox> SITE_URL=https://whattodo72.com bash build-site.sh` (real network, ~4 min; this is the live-source proof; `--skip-dry-run` exists but prints a warning and is refused unless `--i-know` is also given); then swap while holding the build lock (`flock -w 900 ~/whattodo72.com/test/.build.lock`): `build` -> `build.prev-<ts>`, staged `build` in, generated state carried over (events.json, dc-events.json, image-levels.json, all `build/.*` dotfiles), `build-site.sh`/`run-levels.sh`/`pinkpages-levels.orig`/`prices-resolved.json`/`.htaccess` installed via write-temp-then-`mv` (new inode: a running bash keeps its old script), `build/.deployed-sha` written; keep the newest 5 `build.prev-*`; delete the `.deploy/<sha>` dir on success.
- `--rollback` swaps `build` with the newest `build.prev-*` (also restoring the previous top-level scripts: store them inside `build.prev-<ts>/_scripts/` at swap time), under the same lock. `--status` prints deployed sha vs HEAD and the last 3 history lines.
- Failure at any step before the swap leaves prod byte-identical (prove in the selftest with an md5 manifest before/after). Print what will happen and what happened in plain lines; exit codes: 0 ok, 2 refused (dirty/unpushed), 3 preflight failed, 4 dry-run failed, 5 swap failed (with automatic rollback attempted).
- Selftest `bash ops/deploy.sh --selftest` (also auto-run by `tests/deploy.test.sh`, offline, < 90 s): fake remote HOME with a baseline tree; cases: clean deploy swaps and records the sha; generated state survives; bad syntax in a staged file => exit 3, prod unchanged; dry-run failure (stub build-site.sh exiting 1 in staged tree) => exit 4, prod unchanged; lock held by another process => waits then times out with exit 5 (use a tiny `DEPLOY_LOCK_WAIT`), prod unchanged; rollback restores the exact previous tree (md5 manifest); 6th deploy prunes to 5 prev; a deploy during a running (sleeping) old build-site.sh does not break it.
Acceptance: `bash ops/deploy.sh --selftest` exits 0 and prints >= 8 case lines; `bash tests/run-all.sh` exits 0.
Constraints: never print or log the DreamHost password; no GitHub; do NOT run a real deploy against production in this task (T12 does); node/bash compatibility as in T08; `shellcheck` clean if available.

## Result
Files: new `ops/deploy.sh` (CLI + selftest), new `ops/lib.sh` (remote()/remote_extract() + every rf_* remote step), new `tests/deploy.test.sh`; `docs/ARCHITECTURE.md` ("Deploying" section), `docs/AGENTS.md` (`ops/` line replaces "deploy.sh does not exist yet").

Acceptance (Mac, node 22, bash 3.2, no flock: perl flock(2) fallback):
- `bash ops/deploy.sh --selftest` -> `47 passed, 0 failed (13 cases, 37s)`, exit 0 (13 `case N:` lines).
- `bash tests/run-all.sh` -> `ALL PASS: 44 checks/files` (deploy.test.sh auto-discovered, 47 checks).
- DreamHost (node 18.19.1, flock, GNU tools), `git archive | ssh hermes 'ssh dh-backup ...'` into `/tmp/t09.*`, removed after: one clean run `47 passed, 0 failed (13 cases, 43s)` (commit a2f4b22). Later DH runs failed only where node itself aborted/hung at startup (below). Prod: only read-only `--status` (deployed_sha=none, no history.jsonl yet); nothing written. `/tmp` left clean, orphaned test processes killed.

Cases: refusals (dirty, unpushed, --skip-dry-run w/o --i-know) exit 2; bad syntax exit 3; dry-run fail exit 4; lock held -> waits, exit 5; injected swap failure -> auto-rollback, exit 5; clean deploy during a running pre-lock build-site.sh (it finishes on its old inode); generated state carried; rollback = exact md5 of the previous live tree (second rollback swaps forward); lock released mid-wait -> proceeds; 6th deploy prunes to 5; --status; --check; abort/hang retry. Every "prod unchanged" case compares a full md5 manifest.

Extras beyond the brief: `--check` (preflight + dry run, never swaps; useful for T12), `.htaccess`-absent handling, report of untracked build/ files left in build.prev-*, HUP/PIPE ignored during swap.

Open issues:
- **DreamHost node 18 is unreliable under test load**: `pthread_create: Resource temporarily unavailable` then SIGABRT, or a hang at startup (seen in node --check, test-imports, record-run, stub fetch); even `bash: fork: retry` once. Not a per-user count limit I could see (24 tasks, <1 GB VSZ at the time). Sequential `node -e 0` x100: 0 failures. rf_run retries aborts (2x, 15 s apart) and hangs of quick steps; long-step hangs are only bounded (run-all 1200 s, dry run 1800 s). The same failure can hit the cron build (T08 reviewer saw it too). T12 should expect retries and may need to re-run a deploy.
- Because of that, `tests/deploy.test.sh` skips itself inside a deploy preflight (`W72_DEPLOY_PREFLIGHT=1`); it still runs in run-all on the Mac.
- shellcheck not installed on the Mac or the VPS; not run.
- Two-hop `remote_extract` quoting verified into /tmp; first real stage into `.deploy/` is T12.
