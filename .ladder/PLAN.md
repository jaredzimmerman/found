# whattodo72.com scraper hardening: plan

## Goal
Make the whattodo72.com build safe to change and loud when it breaks: one canonical git source tree with a preflighted, reversible deploy; a feed validator that rejects bad feeds before they reach the live site; failure alerts and per-source history; and timeouts, retries and a run lock. **Output of the scraper must not change** except where a task says so (proved by a golden replay).

## Architecture (as it really is, verified 2026-10-07)
- Prod: DreamHost user `indigokarasu`, tree `~/whattodo72.com/test/`. Cron `12 0,7,13,19 * * * /bin/bash $HOME/whattodo72.com/test/build-site.sh >> .../test/logs/build.log 2>&1` (America/Los_Angeles). DH system node **v18.19.1** (node 22 SIGTRAPs there). Tools on DH: flock, timeout, git, rsync, python3, mail/sendmail. No headless Chrome.

- Sources are hand-written functions in `build/fetch.mjs` (2.6k lines, module-level mutable `seen`/`out`), `shared.mjs`, `foopee.mjs`, `sfstation.mjs`, `sucuri.mjs`, `citylights-parse.mjs`, `manual-venues.mjs`, `dc-fetch.mjs`. `row.source` is stripped before writing `events.json`.

- Repo layout mirrors `~/whattodo72.com/test/`: `build/` (source), `build-site.sh`, `run-levels.sh`, `pinkpages-levels.orig`, `prices-resolved.json`, `.htaccess`. New dirs: `ops/`, `tests/`, `docs/`.
- Known defects this plan addresses: prod code hand-edited live (4 of 16 runs died on syntax errors, feed stale ~18 h each, nobody told); `validate_feed` only checks count/days/today (today's string-`categories` feed went live); 66% of events from one unofficial source with no floor/delta guard; `j()` has no explicit timeout, no retries; cron has no lock/timeout; log says "every source fetch succeeded" after "omnivore: unavailable - skipped"; tests hardcode `/tmp/lvtest/...` fixtures and none run in the build.

## Contracts (frozen; changes need a ledger `decision`)
**C1 Deploy unit and state.** Deployed from git: `build/*` source, `build-site.sh`, `run-levels.sh`, `pinkpages-levels.orig`, `prices-resolved.json`, `.htaccess`. NEVER in git and NEVER overwritten by deploy: `build/events.json`, `build/dc-events.json`, `build/image-levels.json`, `build/.*` (dotfiles), `logs/`, `.build.lock`, `build.prev-*`. `.gitignore` encodes this.
**C2 Source report.** `fetch.mjs` writes `build/.source-report.json` before exit: `{"generatedAt":ISO,"sources":{"<name>":{"status":"ok|failed|skipped","reason":string|null,"registered":int,"kept":int}},"totals":{"kept":int}}`. `<name>` = the value of `row.source` (lower-case, stable; every registered row must carry one). `kept` = rows surviving to events.json. `skipped` = module unavailable (e.g. omnivore/playwright). Final log line says "every source fetch succeeded" only if no source is `failed` and none is `skipped`; otherwise it lists them.
**C3 Floors.** `build/source-floors.json`: `{"<name>":{"min":int,"required":bool}}`. required+below-min -> fatal; optional -> warning. Seeded conservatively from the run history below (dothebay required min 60; others optional).
**C4 Validator.** `node build/validate-feed.mjs --events F --report R --floors P --history H [--live-url U] [--accept-delta]`; module also exports `validateFeed(feed, ctx)`. Exit 0 = ok (warnings printed), 1 = fatal. Writes `build/.validate-report.json` `{ok,fatal:[],warnings:[],stats}`. Checks: (a) schema per event: `id` non-empty string unique; `title` non-empty string; `date` YYYY-MM-DD and in `days`; `startMinutes`,`endMinutes` ints; `timeLabel` string; `venue` string|null; `address` string|null; `categories` an array of strings drawn from the known taxonomy (an EMPTY array is a warning, not fatal: SF Station rows are uncategorised by design; a non-array or string is fatal) (derive the list from fetch.mjs, single source of truth); `url` http(s) string; `linkTier` in {venue,boxoffice,listing,aggregator}; `priceTier` string; no `source` key; (b) feed envelope: `days` has 3 entries and includes today (Pacific); (c) floors; (d) delta: total below 60% of the median of the last 7 `published` runs in history (or of the live feed total if history is shorter than 3) -> fatal; above 160% -> warning only; `--accept-delta` or a one-shot file `build/.accept-delta` (consumed on use) downgrades a delta fatal to a warning. **Regression test:** the 2026-10-07 bad feed (12 events with string `categories`, venue `null`) must be rejected.
**C5 History and status.** `logs/history.jsonl` (append-only, trimmed to the last 500 lines): `{"ts","run_id","outcome":"published|rejected|fatal|dry-run|stage-only|locked-skip","stage","total","sources":{name:kept},"duration_s","sha","warnings":int,"fatal":[...]}`. `logs/status.json` (overwritten each run, private: `/test/logs/` is 404 by design): `{"last_attempt":{ts,run_id,outcome,stage},"last_success":{ts,run_id,total}|null,"consecutive_failures":int,"sources":{name:{kept,zero_streak}},"deployed_sha":string|null,"feed_generatedAt":ISO}`. Per-run console log kept at `logs/runs/<run_id>.log` (last 30).
**C6 Lock and limits.** `build-site.sh` takes `flock -n` on `~/whattodo72.com/test/.build.lock`; if held, logs, writes history outcome `locked-skip`, exits 0. Overall `timeout 25m` on the whole script; `node fetch.mjs` under `timeout 15m`. A `trap` always writes history/status, including on FATAL.
**C7 HTTP helper.** `build/http.mjs`: `getJson(url,opts)`, `getText(url,opts)`, `deadline`. Per-attempt timeout 20 s (json) / 30 s (text); retries 2 (backoff 1 s, 3 s +- jitter; honor `Retry-After` up to 30 s) on network error/408/425/429/5xx, never on other 4xx; a global deadline (`FETCH_DEADLINE_MS`, default 12 min) after which calls throw `DeadlineError` immediately and `fetch.mjs` exits non-zero. Failures still go through the existing `noteFailure` ledger. Existing request headers and pacing are unchanged. No raw `fetch(` remains in source modules outside `http.mjs`.
**C8 Modes of build-site.sh** (env): default = production behavior; `DRY_RUN=1` runs stages 0-3 only against sandbox `ROOT`, writes the validate report, never touches `/test` or live; `STAGE_ONLY=1` publishes to `/test` and stops before promote; `ROOT` overrides the docroot (default `$HOME/whattodo72.com`).
**C9 Deploy.** `ops/deploy.sh` (runs on the Mac): requires a clean tree and a commit already pushed to `origin`; `git archive` -> `ssh hermes ssh dh-backup` into `~/whattodo72.com/test/.deploy/<sha>/`; remote preflight with DH node 18 (`node --check` every .mjs, `bash -n` every .sh, `test-imports`, offline unit tests via `tests/run-all.sh`); remote `DRY_RUN=1` build of the staged tree; then, holding the build lock, atomic swap (`build` -> `build.prev-<ts>`, staged `build` in, generated state carried over, scripts renamed in place), writes `build/.deployed-sha`; keeps 5 `build.prev-*`. `--rollback` swaps back to the newest `build.prev-*`. Any failure before the swap leaves prod untouched.
**C10 Replay harness.** `tests/replay/`: `record` (run on DH: wraps fetch + curl HEAD, writes `fixtures/<sha1(method url)>.json` `{status,headers,bodyBase64}` + `meta.json` with the frozen "now"), `replay-preload.mjs` (`node --import`: serves fixtures, throws on a miss, freezes `Date`), `run.sh` (runs `fetch.mjs` in a temp copy of `build/`, compares `events.json` to `tests/golden/events.golden.json` ignoring `generatedAt`). Two replays of unchanged code are byte-identical. `fixtures/` is gitignored; a tarball is kept at `hermes:/root/backups/whattodo72-fixtures-<date>.tgz`.
**C11 Alerts.** Detection lives OUTSIDE DreamHost (a dead build cannot report its own death): `ops/watchdog.py` on the VPS reads `logs/status.json` via ssh plus the public `events.json` every 30 min. Alert when: last success older than 14 h; last outcome is rejected/fatal (once per run_id); a required source has `zero_streak` >= 3; public `generatedAt` older than 14 h or feed unreadable; DH unreachable. Re-alert the same condition at most every 6 h; send a recovery message. Delivery: `hermes send` to the home channel (decision D1). `--dry-run` prints instead of sending.
